# 广州大学研究生课表 · 手机轻量版

把 `https://yjsyxt.gzhu.edu.cn/gsapp/sys/yddwdkbapp/*default/index.do#/` 的课表，
做成一个手机上秒开、自带登录的极简页面。

> **两种形态，共用同一套代码：**
> - **本目录（服务器版）**：Node 单文件服务，手机浏览器访问，需要一个常开的设备。
> - **`../android/`（安卓 App）**：49 KB 的 APK，纯本地运行，不依赖电脑。
>   两者共用 `public/` 下的同一份 HTML/CSS/JS，改 UI 只需改这里。

- 服务端：**Node.js 单文件、零第三方依赖**（只用内置 `https`/`http`/`vm`/`crypto`）
- 前端：**一个 HTML + 一个 CSS + 一个 JS**，无框架、无构建
- 登录：服务端代做 CAS 认证，前端只填学号密码
- 只读课表，不写入学校系统任何数据

---

## 一、先说结论：这件事为什么可行

逆向确认了三件事（都已实测跑通）：

| 环节 | 实际情况 | 对实现的影响 |
| --- | --- | --- |
| 认证方式 | CAS 单点登录 `newcas.gzhu.edu.cn`，账号密码登录**无验证码** | 可以服务端代登录 |
| 密码保护 | 不是真加密，而是页面自带 `des.js` 里的 `strEnc(un+pd+lt,'1','2','3')`，密钥硬编码 | 可在 Node 里复用同一份算法，登录完全可复现 |
| 数据接口 | 课表有独立 JSON 接口，不依赖页面渲染 | 可自建 UI，不需要抓网页 |

**关键坑（踩过才知道）**：业务路径里的 `*` 必须原样发送。
`/gsapp/sys/yddwdkbapp/*default/index.do` 里的 `*` 一旦被 URL 编码成 `%2A`，
服务端直接返回 403（一个 GIF 图片，很容易被误判成"没权限"）。
所以本项目的 HTTP 层**不经过 WHATWG URL 规范化**，path 原样透传。

## 二、用到的接口（逆向结果）

Base：`https://yjsyxt.gzhu.edu.cn`，均需先登录拿到 `GS_SESSIONID`。

| 接口 | 参数 | 用途 |
| --- | --- | --- |
| `POST /gsapp/sys/yddwdkbapp/modules/wdkb/kfdxnxqcx.do` | — | 可选学年学期列表（24 个） |
| `POST /gsapp/sys/yddwdkbapp/modules/wdkb/getXnxqdyzc.do` | — | 当前周次 + 本周每天日期 |
| `POST /gsapp/sys/yddwdkbapp/modules/wdkb/xsskjccx.do` | `XNXQDM` `XH` | 节次方案（11 节及起止时间） |
| `POST /gsapp/sys/yddwdkbapp/modules/wdkb/xspkjgcx.do` | `XNXQDM` `*order=+KCDM,-ZCBH,+XQ,+KSJCDM` | **课表数据本体** |

课表记录字段（`xspkjgcx` 返回）：

| 字段 | 含义 |
| --- | --- |
| `KCMC` / `KCDM` | 课程名称 / 课程代码 |
| `JASMC` | 教室（`★B1栋203` 这类） |
| `JSXM` | 任课教师 |
| `XQ` | 星期（1=周一 … 7=周日） |
| `KSJCDM` / `JSJCDM` | 起始 / 结束节次代码 |
| `ZCBH` | **30 位周次位图**，第 i 位为 `1` 表示第 i 周上课 |
| `ZCMC` | 周次文字描述，如 `3-10周` |
| `KSSJ` / `JSSJ` | 起止时间，形如 `830` = 08:30 |

两个必须处理的细节：

1. **上游按"节次"逐条返回**。一门连上 2 节的课会有 2 条记录，
   直接渲染会变成两个碎块。`buildGrid()` 里按「同一天 + 同课程 + 节次相接」合并。
2. **`ZCBH` 位图比 `ZCMC` 更适合判断某周是否有课**，所以按 `ZCBH[week-1] === '1'` 过滤。

## 三、跑起来

```bash
cd server
node server.js
```

- 本机：`http://127.0.0.1:8899`
- 手机同 WiFi：`http://<电脑局域网IP>:8899`

可用环境变量：`PORT`（默认 8899）、`HOST`（默认 `0.0.0.0`）。

### 拿手机访问的两种方式

1. **局域网直连**（最快，适合自己用）
   电脑和手机连同一个 WiFi，手机浏览器打开 `http://<电脑IP>:8899`，
   然后「添加到主屏幕」，用起来跟 App 一样。

2. **部署到有公网的小服务器**
   只要能跑 Node 就能跑，内存占用几十 MB。注意用 HTTPS（下面单独说）。

## 四、安全须知（重要）

- 账号密码**只在服务进程内存里**用于换取课表，不写数据库、不落盘。
  `server.js` 里除了课表接口调用没有任何持久化。
- 会话默认 **12 小时无操作自动失效**，前端只保存一个 HttpOnly 的随机 `sid`。
- 前端「记住学号」只用 `localStorage` 存**学号**，不存密码。
- ⚠️ 如果部署到公网，**务必加 HTTPS**（如 Caddy/Nginx 反代 + 证书），
  否则登录请求里的密码会在链路上明文传输。
- 只建议自己或小范围使用，不要公开传播（这毕竟是绕过了学校 App 的入口）。

## 五、企业微信里有现成功能吗？

分三种情况看：

**1. 企业微信自带的「日程」——不适用于你的课表。**
企微的日程/会议是**手动创建或 ICS 订阅**的。西安建大等学校做过
["企业微信日程同步课表"](https://nic.xauat.edu.cn/info/1139/8120.htm)，
但那是**学校信息中心在后台做的对接**，属于校级项目，学生个人无法自助开启。
而且广州大学研究生系统目前没有对外提供 ICS/CalDAV 接口，
所以这条路对你走不通。

**2. 企微「工作台」里能不能直接加这个课表？**
可以，但只是**加个网页链接**（自建应用 → 网页应用，填上系统 URL）。
点进去还是原来那个又重又慢的页面，且强制走微信 OAuth 登录 ——
等于只是换了个入口，没解决"轻量化"。

**3. 真正可行的企微整合方式：**
把本项目部署到一台学校内网/公网可达的服务器，
然后在企业微信自建应用里把地址指向**本项目的地址**。
效果是：从企微工作台点进去 → 秒开轻量课表 → 只用输一次学号密码。
这样"轻量 + 登录"两个要求都满足了，且不需要企微开放任何特殊接口。

> 前提：企微自建应用需要管理员权限才能创建。如果你是学生，
> 这条路要走通得找学院/信息中心，或者**干脆不做企微集成**，
> 直接用第五节的下沉方案（手机主屏快捷方式）。

## 六、更低成本的替代路线（按推荐度排序）

| 方案 | 成本 | 体验 | 说明 |
| --- | --- | --- | --- |
| **本项目 + 添加到主屏幕** | 一台常开的电脑/小主机 | ⭐⭐⭐⭐ | 一次登录 12 小时有效，秒开 |
| 本项目 + 公网小服务器 | 几元/月 | ⭐⭐⭐⭐⭐ | 随时随地可用，需配 HTTPS |
| 手机浏览器书签存原页面 | 0 | ⭐⭐ | 原页面重、每次要重新登录，就是你现在嫌烦的那种 |
| 第三方课表 App（如"小爱课程表"）导入 | 0 | ⭐⭐⭐ | 有 [正方教务适配教程](https://blog.csdn.net/MUKOU_AOI/article/details/146875119)，但需手动抓数据导入，且研究生系统的接口常不兼容 |
| 企业微信日程同步 | 需学校信息中心配合 | ⭐⭐⭐⭐⭐ | 体验最好，但**不是个人能自助完成的** |

## 七、代码结构

```
server/
├── server.js            单文件服务：CAS 登录 / 会话 / 课表接口 / 静态资源
├── des.js               学校 CAS 自带的 DES 实现（strEnc），原样复用
├── public/
│   ├── index.html       登录页 + 课表页
│   ├── style.css        移动端优先样式
│   └── app.js           前端逻辑（约 300 行，无框架）
├── test-client.js       端到端测试（登录 → 学期 → 周次 → 课表）
└── shot.js              无头浏览器截图验证（开发用）
```

### HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/login` | body `{username, password}`，成功返回姓名 |
| `POST` | `/api/logout` | 销毁会话 |
| `GET` | `/api/state` | 当前是否已登录 |
| `GET` | `/api/terms` | 学期列表 |
| `GET` | `/api/week` | 当前周次与日期 |
| `GET` | `/api/kb?term=&week=` | 课表（已整理成网格直接可渲染） |

`/api/kb` 会对每门课补齐 `from`（起始节次序号）、`to`、`span`（跨几节）和
`color`（按课程代码稳定分配的颜色），前端只管画。

## 八、上游接口变更时会怎样

- **CAS 登录页改版**（`lt` / `execution` 字段没了）→ 登录会报
  「无法获取 CAS 登录票据(lt)」，需要重新对照登录页更新选择器。
- **`code` 约定变化** → 接口会报「接口 xxx 返回 code=...」。
- **课表字段改名**（如 `XQ` → 其他）→ 在 `server.js` 的 `courses()` 里改映射即可，
  前端不用动。

排查手段：`recon/` 目录里留了逆向过程的脚本（`api*.js`、`cdp.js`），
其中 `cdp.js` 用无头浏览器抓真实请求，接口变了重新跑一遍就能看到新接口。
